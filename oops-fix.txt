The primary security issue identified is the **unencrypted storage of the Gemini API key** in `~/.oops_config.json`. Storing sensitive credentials in plaintext on the local filesystem makes them vulnerable to exposure if the user's system is compromised.

To address this, we will implement symmetric encryption for the Gemini API key using a user-provided passphrase. This passphrase will be used to derive an encryption key, and the API key will be encrypted using `AES-256-GCM` (Galois/Counter Mode), which provides both confidentiality and data integrity.

Here's how the fix will work:

1.  **Encryption during setup**: When a user configures the Gemini API key, they will also be prompted to set a strong passphrase. This passphrase will never be stored.
2.  **Key Derivation**: A cryptographically secure random salt will be generated, and the passphrase, combined with this salt, will be used by PBKDF2 (Password-Based Key Derivation Function 2) to derive a strong encryption key.
3.  **AES-256-GCM Encryption**: The API key will be encrypted using AES-256-GCM. This mode requires an Initialization Vector (IV) and produces an Authentication Tag (AuthTag) in addition to the ciphertext.
4.  **Secure Storage**: The `encryptedApiKey`, `salt`, `iv`, and `authTag` will be stored in `~/.oops_config.json`. The original plaintext `apiKey` field will be cleared.
5.  **Decryption on Demand**: Whenever the Gemini API key is needed (for a review or fix generation), the user will be prompted to enter their passphrase. This passphrase will be used with the stored salt, IV, and AuthTag to decrypt the API key.
6.  **Backward Compatibility & Migration**: If an existing `~/.oops_config.json` contains a plaintext API key, the system will detect it, issue a warning, and prompt the user to reconfigure and encrypt their key. In pre-commit mode, using an unencrypted key will block the commit, enforcing the security improvement.
7.  **Error Handling**: Multiple attempts for passphrase entry will be allowed, and failures (incorrect passphrase, missing data) will be handled gracefully, either by preventing the AI review or blocking the commit as appropriate for the context.

+function encrypt(text, passphrase) {
+    const salt = crypto.randomBytes(SALT_LENGTH);
